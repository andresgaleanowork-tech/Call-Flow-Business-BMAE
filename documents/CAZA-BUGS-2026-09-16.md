## 🔴 ALTA

### BUG-1 ✅ · La fábrica CI fallaría en el primer push (step APK)
**Dónde**: `.github/workflows/build.yml`, step "Compilar APK".
**Qué**: `env: ANDROID_SDK_ROOT: ${{ env.ANDROID_SDK_ROOT }}` — el contexto `env` de Actions **no contiene** las variables del runner → evalúa a **cadena vacía** → el step exporta `ANDROID_SDK_ROOT=""` → `build.sh` cae al fallback `$HOME/.local/android-sdk` (inexistente) → **aapt2 not found → step rojo**.
**Fix (2 líneas)**:
```yaml
# borrar el bloque env: entero; dentro del run, primera línea:
SDK="${ANDROID_SDK_ROOT:-$ANDROID_HOME}"
```
y endurecer: si falta `build-tools/34.0.0`, sdkmanager lo instala (hoy solo se asume).

### BUG-2 ✅ · La racha miente tras medianoche (UTC vs hora local)
**Dónde**: plantillas pymes + residencial, `bumpVid()`: `var hoy=(new Date()).toISOString().slice(0,10)` (**UTC**), mientras `racha()` cuenta con componentes **locales**.
**Repro dinámica (T4)**: reloj falso `2026-09-17 00:30 Europe/Madrid` → `bm_stats.dias=["2026-09-16"]` (¡ayer!) pero hoy local es el 17.
**Consecuencia**: practicar entre 00:00–01:59 (verano) / 00:00–00:59 (invierno) se anota al día anterior → huecos falsos en la racha, insignias 🔥🌟👑 que no saltan o saltan tarde. Dos sesiones a caballo de medianoche cuentan como un solo día.
**Fix**: helper `hoyLocal()` con `getFullYear/getMonth/getDate` en `bumpVid` (mismo patrón que ya usan `racha()` y el panel admin) + homogeneizar `desde`, `creado` y fechas de insignias.

## 🟡 MEDIA

### BUG-3 ✅ · CRM: fichas con apóstrofo → botones muertos
**Dónde**: plantillas ×2, `cliListaHtml()`: `onclick="cliBorraNota(decodeURIComponent(\''+enc+'\'),…)"` con `enc=encodeURIComponent(nombre)` — **encodeURIComponent NO codifica `'`**.
**Repro dinámica (T3)**: cliente `L'Olivé Tarrés` → click real al ✕ → `SyntaxError: missing ) after argument list`. Afecta a los 3 botones (borrar nota, copiar historial, borrar ficha).
**Fix**: `.replace(/'/g,'%27')` tras el encodeURIComponent en `cliListaHtml`.

### BUG-4 ✅ · El ✕ del aviso ✨ «hay versión nueva» no recuerda nada
**Dónde**: plantillas ×2, `aviso()`: escribe `localStorage.setItem('cfb_ver_visto', v.version)` **crudo**, pero lee con `LSg()` que hace `JSON.parse` → `parse('2.4.0')` lanza → devuelve `''` → condición nunca cierta.
**Consecuencia**: el banner reaparece en cada arranque aunque el usuario lo cierre (justo lo que prometía no hacer).
**Fix**: `try{ localStorage.setItem('cfb_ver_visto', JSON.stringify(v.version)); }catch(e){}`.

### BUG-5 ✅ · `version.json` remoto se pinta sin sanear (endurecer)
**Dónde**: plantillas ×2, `aviso()`: `<b>v'+v.version+'</b> ('+(v.fecha||'hoy')+')` y `href="'+(v.url||'#')` tal cual.
**Repro dinámica (T5)**: JSON hostil (fetch stub) → `<img onerror>` creado en el DOM + `href="javascript:alert(1)"`. Es la **única entrada de datos remotos** de la app; el endpoint es nuestro, pero defensa en profundidad obligada (cuenta comprometida, DNS…).
**Fix**: `xh()` en version/fecha + url solo si casa `^https://`.
