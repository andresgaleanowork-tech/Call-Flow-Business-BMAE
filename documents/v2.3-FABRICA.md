# 🏭 v2.3 «Fábrica» — CI, auto-aviso de versión y registro de errores

**Fecha:** 15‑09‑2026 · **Qué entra:** workflow GitHub Actions · auto-aviso EXE/APK → web oficial · `bm_errores` que viaja en la ficha de soporte

---

## 1 · CI: cada push = binarios listos para repartir

Workflow en `.github/workflows/build.yml` (rama `main`, también manual con «Run workflow»):

| Paso | Qué hace |
|---|---|
| **QA** | `npm test` en WEB (155/155 + 58/58; incluye el golden hash editorial — si un HTML se tocó a mano, el build **falla** aquí) |
| **EXE** | Go cross-compile Windows con los 5 HTML de `apps/windows/lanzador/assets/` |
| **Firma** | Si existen `secrets.CFB_CERT_B64` + `CFB_CERT_PASS` → EXE firmado de verdad (osslsigncode + sello RFC‑3161 DigiCert). Sin secretos → copia sin firmar (el flujo no se rompe) |
| **APK** | Java 21 + SDK del runner → `apps/android/proyecto/build.sh` |
| **Artifacts** | «call-flow-business-<sha>»: exe + firmado + apk + SHA256.txt, retenidos 30 días |

### Cuando compréis el certificado real (una sola vez)
```bash
# conviertes el .pfx al secreto (en un PC de confianza, NUNCA subas el pfx)
base64 -w0 firma-real.pfx  → Settings → Secrets and variables → Actions → New repository secret
  CFB_CERT_B64   = (salida del base64)
  CFB_CERT_PASS  = (contraseña del pfx)
```
A partir de ahí cada push entrega EXE firmado real sin tocar nada.

## 2 · Auto-aviso de versión en EXE/APK (sin reinstalar)

- Antes, el aviso ✨ solo funcionaba en la web (http). Ahora: **si hay URL oficial configurada, EXE y APK también la preguntan**.
- Activación (una vez, cuando tengáis la página publicada): edita en `tools/factory/plantillas/pymes.html` y `residencial.html`:

```js
window.CFB_UPDATE_URL='https://USUARIO.github.io/REPO/version.json';
```
→ `node tools/factory/build.js` → tests → binarios. Sin URL, EXE/APK siguen en silencio (comportamiento de antes).
- En la APK, tocar el enlace del aviso abre el **navegador de sistema** (el WebView ya no se traga la web), y `mailto:`/`tel:` también salen fuera — ver `MainActivity.shouldOverrideUrlLoading`.

## 3 · Registro de errores del dispositivo (`bm_errores`)

- Atrapa errores JS y promesas rotas; tope 20 entradas, mensajes ≤400 caracteres.
- En «Mi semana »→ Utilidades: **📋 Registro de errores (N)** copia el historial · **🧼 Vaciar registro** lo limpia.
- La **ficha de soporte** (botón ✍️ Proponer mejora → canalpymes@bmae.es) incluye ya `REGISTRO DE ERRORES …` — el usuario puede borrarlo antes de enviar si no aplica.
- Sincroniza con el equipo como todo `bm_*` (sin datos personales: solo tipo, mensaje y archivo:línea) → el panel no lo pinta, pero está en la burbuja.

## Cadencia resultante (viernes feliz)
1. Editar `contenido/…` → `npm run build:editorial` → `git push`.
2. **El repo hace el resto**: tests, exe, apk, firma (si hay cert), zips descargables.
3. Repartir el zip de Artifacts por Teams. La app misma avisa de la próxima versión desde dentro (2).
